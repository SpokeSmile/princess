# Сервер «Тихоречья»

Django хранит ход расследования в SQLite и обращается к Groq API. Проверка даты, подсказки и личное письмо остаются на сервере. Ответы модели не управляют состоянием игры и не открывают финал.

## Локальный запуск

Нужен **Python 3.10 или новее**. На компьютере разработки окружение уже создано в `backend/.venv`; стандартный системный Python macOS 3.9 для этого проекта не подходит.

Из корня проекта:

```sh
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.lock
cp backend/.env.example backend/.env
backend/.venv/bin/python backend/manage.py migrate
backend/.venv/bin/python backend/manage.py runserver 127.0.0.1:8000
```

Если `.venv` уже создана, повторять создание не нужно. Если `.env` уже существует, сохраняй его содержимое: команда `cp` выше предназначена для первого запуска.

Открой **http://127.0.0.1:8000/**. В локальном режиме Django раздаёт существующие `index.html`, `/src/` и `/public/` из корня проекта. Сайт и API должны открываться с одного адреса: тогда сессии и CSRF работают без CORS.

## Ключ Groq

Вставь ключ только в **`backend/.env`**:

```dotenv
GROQ_API_KEY=ваш_ключ
GROQ_MODEL=qwen/qwen3.8-27b
```

Перезапусти сервер после изменения `.env`. Ключ не нужен для просмотра письма, изучения документов, этапа с фильмом и проверки даты.

`qwen/qwen3.8-27b` — модель по умолчанию. В режиме диалога рассуждения отключены, ответ ограничен 220 токенами. Другую доступную модель можно указать в `GROQ_MODEL`. Для работы без оплаты оставайтесь на Free tier Groq; точные квоты смотрите в своём аккаунте. Приложение не меняет тариф, не покупает кредиты и не переключается автоматически на другую модель.

Если ключ отсутствует, `/api/chat/` возвращает `503 ai_not_configured` с понятным сообщением. Скриптовые ответы не выдаются за ответы нейросети. При ошибке доступа, ограничении квоты или тайм-ауте новое сообщение не попадает в историю: вопрос можно повторить позже.

## Сценарий и API

Новый сюжет называется «Письмо без даты» и использует отдельный ключ сессии `date_investigation_id`. Прежние записи расследования сохраняются. Перед запуском примените миграции, включая `0004_investigation_date_story`.

Проверка даты доступна сразу. Фильм не блокирует правильный полосатый шаблон. После совпадения даты `solved=true`, но личное письмо выдаётся только после отдельного `POST /api/letter/`; затем оно доступно и через состояние при перезагрузке.

| Метод | Путь | Запрос |
|---|---|---|
| GET | `/api/game/` | Состояние и CSRF-токен |
| POST | `/api/evidence/` | `{ "id": "registry" }` |
| POST | `/api/month/` | `{ "answer": "..." }` |
| POST | `/api/film/` | `{ "answer": "..." }` |
| POST | `/api/stamp/` | `{ "pattern": "stripes" }` (`checks` / `dots` также допустимы) |
| POST | `/api/date/` | `{ "answer": "..." }` |
| POST | `/api/letter/` | `{}` |
| POST | `/api/hint/` | `{ "stage": "month", "level": 1 }` |
| POST | `/api/chat/` | `{ "message": "..." }` |
| POST | `/api/reset/` | `{}` |

Материалы: `envelope`, `registry`, `film`, `stamp`, `calendars`. Этапы подсказок: `month`, `film`, `stamp`, `year`. Третий уровень требует `confirm: true`; подсказки выдаются последовательно и сохраняются в `hint_log`. Поле `run_id` защищает запрос от применения к уже сброшенному делу, `revision` упорядочивает ответы.

`/api/game/`, `/api/evidence/`, `/api/reset/`, `/api/letter/` возвращают состояние напрямую. Остальные действия возвращают `state` и результат действия. Во все POST передаются `Content-Type: application/json`, cookie сессии, `X-CSRFToken` и текущий `run_id`. Ответы API имеют `Cache-Control: no-store, private`.

Сюжетные сообщения имеют `source: "script"`, ответы Groq — `source: "groq"`. Обязательные переходы, проверка даты, подсказки и открытие письма не вызывают модель. На «Что делать?» персонаж называет конкретное действие текущего этапа; на вопрос о фильме объясняет функцию узора.

Модель получает только открытые материалы и найденные части. Готовая дата, значение этого дня и личное письмо в контекст не входят. Дополнительный фильтр скрывает личные обращения и преждевременную разгадку в ответах.

Лимит: 60 обращений к Groq на сессию, 1500 символов на вопрос, пауза 2 секунды. Сброс дела не обнуляет квоту. При ошибке провайдера не появляется выдуманный ответ; документы и подсказки продолжают работать. Новые автотесты не создавались и не запускались.

## Развёртывание на своём сервере

1. Скопируй весь проект, включая `backend/`, `src/`, `public/` и корневой `index.html`.
2. Создай `.venv`, установи `backend/requirements.lock`, создай базу командой `manage.py migrate`.
3. В `.env` или переменных окружения сервиса задай:

```dotenv
DJANGO_DEBUG=false
DJANGO_SECRET_KEY=длинное_случайное_значение
DJANGO_ALLOWED_HOSTS=example.com,www.example.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://example.com,https://www.example.com
GROQ_API_KEY=ваш_ключ
GROQ_MODEL=проверенная_бесплатная_модель
```

4. Настрой Gunicorn через образец `deploy/tihorechye.service.example`. Замени путь проекта и пользователя сервиса. Если используется `EnvironmentFile`, храни файл с секретами отдельно от публичного каталога, например `/etc/tihorechye.env` с правами `600`.
5. Настрой Nginx по `deploy/nginx.conf.example`: свой домен, путь проекта и действующие TLS-сертификаты. Папки `/src/` и `/public/` раздаются как статические; `/` и `/api/` передаются Django. `backend/`, `.env`, `.venv` и SQLite наружу не раздаются.
6. Пользователь сервиса должен иметь право читать проект и писать файл базы и её родительский каталог. Сохрани резервную копию `backend/db.sqlite3` перед переносом уже существующего прогресса.

При `DJANGO_DEBUG=false` включаются secure cookies, перенаправление на HTTPS и базовые HSTS-заголовки; `X-Forwarded-Proto` доверяется только при работе за указанным локальным Nginx. Встроенный `runserver` предназначен для разработки.

Статическое размещение само по себе не запускает Python/Django: полноценный чат и серверная проверка версии работают после запуска этого backend на твоём сервере. Ключ не требуется помещать в браузерный JavaScript или в настройки статического сайта.


## Vercel

Для размещения всего проекта на Vercel используйте [deploy/VERCEL.md](deploy/VERCEL.md). Корневые `manage.py`, `requirements.txt` и `vercel.json` подготовлены для Django. SQLite используется только локально; на Vercel обязателен `DATABASE_URL` PostgreSQL.
