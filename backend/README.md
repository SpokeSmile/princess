# Сервер «Тихоречья»

Django хранит ход расследования в SQLite и обращается к Mistral API. Настоящее имя отправителя и проверка версии остаются на сервере. Ответы модели не управляют состоянием игры и не открывают финал.

## Локальный запуск

Нужен **Python 3.10 или новее**. На компьютере разработки окружение уже создано в `backend/.venv`; стандартный системный Python macOS 3.9 для этого проекта не подходит.

Из корня проекта:

```sh
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.lock
cp backend/.env.example backend/.env
backend/.venv/bin/python backend/manage.py migrate
backend/.venv/bin/python backend/manage.py runserver 127.0.0.1:8000
```

Если `.venv` уже создана, повторять создание не нужно. Если `.env` уже существует, сохраняй его содержимое: команда `cp` выше предназначена для первого запуска.

Открой **http://127.0.0.1:8000/**. В локальном режиме Django раздаёт существующие `index.html`, `/src/` и `/public/` из корня проекта. Сайт и API должны открываться с одного адреса: тогда сессии и CSRF работают без CORS.

## Ключ Mistral

Вставь ключ только в **`backend/.env`**:

```dotenv
MISTRAL_API_KEY=ваш_ключ
MISTRAL_MODEL=mistral-small-latest
```

Перезапусти сервер после изменения `.env`. Ключ не нужен для просмотра письма, изучения документов, этапа с фильмом и проверки версии отправителя.

`mistral-small-latest` — пример из документации Mistral, а не обещание бесплатного доступа к этой модели. Перед использованием проверь доступную модель и квоты своего аккаунта в Free mode. Приложение не включает pay-as-you-go, не меняет модель при ошибках и не покупает кредиты, но API-запросы будут подчиняться тарифу настроенного аккаунта. Чтобы сохранить нулевые расходы, используй ключ аккаунта в Free mode и доступную в нём модель.

Если ключ отсутствует, `/api/chat/` возвращает `503 ai_not_configured` с понятным сообщением. Скриптовые ответы не выдаются за ответы нейросети. При ошибке доступа, ограничении квоты или тайм-ауте новое сообщение не попадает в историю: вопрос можно повторить позже.

## Проверка

```sh
backend/.venv/bin/python backend/manage.py check
backend/.venv/bin/python backend/manage.py test quest
```

Тесты проверяют этап с фильмом, блокировку ранней разгадки, варианты ответа на вопрос фильма, серверную проверку имени, отсутствие спойлеров в контексте модели, независимость сессий, CSRF, лимиты через сброс, отказ без ключа, обработку ошибок провайдера и сохранение истории. Сброс и разгадка во время ожидающего ответа Mistral также проверяются. Вызовы Mistral в тестах подменены; оплачиваемые запросы не выполняются.

## API

Все ответы API имеют `Cache-Control: no-store, private`. До разгадки поле `identity` отсутствует.

| Метод | Путь | Запрос | Ответ |
|---|---|---|---|
| GET | `/api/game/` | — | Состояние расследования и `csrf_token` |
| POST | `/api/evidence/` | `{ "id": "letter" }` | Состояние; повторная находка идемпотентна |
| POST | `/api/chat/` | `{ "message": "..." }` | `{ "reply": "...", "state": { ... } }` |
| POST | `/api/film/` | `{ "answer": "..." }` | `{ "correct": true/false, "message": "...", "state": { ... } }` |
| POST | `/api/guess/` | `{ "answer": "..." }` | `{ "correct": true/false, "message": "...", "state": { ... } }` |
| POST | `/api/reset/` | `{}` | Чистое состояние нового расследования |

Допустимые идентификаторы материалов: `letter`, `envelope`, `registry`, `recording`.

В состоянии есть `film_unlocked` и `film_solved`. Когда изучены письмо и ещё один документ, в историю один раз добавляется вопрос о фрагменте фильма «До встречи с тобой», 01:02:43–01:03:30. Ответ проверяется сервером; личный смысл эпизода не раскрывается. Правильный короткий ответ можно отправить как через `/api/film/`, так и в `/api/chat/`, даже без ключа Mistral. Это сценарное действие не расходует квоту API. До проверки фрагмента отправителя подтвердить нельзя.

Сценарные реплики ассистента помечены `source: "script"`, ответы настоящего Mistral — `source: "mistral"`. Показывай происхождение сообщения в интерфейсе; сценарий не является ответом вызванной модели.

Для POST отправляй `Content-Type: application/json`, `X-CSRFToken` из последнего состояния и cookies (`credentials: "same-origin"`). Сессия содержит только закрытый идентификатор записи в базе; переписка и улики хранятся на сервере.

Ограничения чата: 1500 символов на вопрос, не более 60 обращений к провайдеру за браузерный сеанс, пауза 2 секунды между запросами. При генерации передаются только последние 12 реплик, доступные факты и текущее сообщение. Выход модели ограничен 220 токенами. Задержки/лимиты провайдера могут быть строже. Сброс расследования не обнуляет лимит и задержку чата. Ошибочные обращения к провайдеру также учитываются в лимите, поскольку сам запрос уже был отправлен. Одновременные запросы одной сессии блокируются через базу, включая несколько процессов Gunicorn.

Сброс помечает прежнее дело закрытым для изменений. Если старый запрос чата завершится после сброса, сервер вернёт `409 case_reset` без старого состояния; интерфейсу следует обновить текущий сеанс.

При подтверждении версии сервер устанавливает `solved=true`, сообщает, что личность установлена, и запрещает дальнейший чат. Приглашение, романтическое письмо или новый сюжет не открываются.

## Развёртывание на своём сервере

1. Скопируй весь проект, включая `backend/`, `src/`, `public/` и корневой `index.html`.
2. Создай `.venv`, установи `backend/requirements.lock`, создай базу командой `manage.py migrate`.
3. В `.env` или переменных окружения сервиса задай:

```dotenv
DJANGO_DEBUG=false
DJANGO_SECRET_KEY=длинное_случайное_значение
DJANGO_ALLOWED_HOSTS=example.com,www.example.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://example.com,https://www.example.com
MISTRAL_API_KEY=ваш_ключ
MISTRAL_MODEL=проверенная_бесплатная_модель
```

4. Настрой Gunicorn через образец `deploy/tihorechye.service.example`. Замени путь проекта и пользователя сервиса. Если используется `EnvironmentFile`, храни файл с секретами отдельно от публичного каталога, например `/etc/tihorechye.env` с правами `600`.
5. Настрой Nginx по `deploy/nginx.conf.example`: свой домен, путь проекта и действующие TLS-сертификаты. Папки `/src/` и `/public/` раздаются как статические; `/` и `/api/` передаются Django. `backend/`, `.env`, `.venv` и SQLite наружу не раздаются.
6. Пользователь сервиса должен иметь право читать проект и писать файл базы и её родительский каталог. Сохрани резервную копию `backend/db.sqlite3` перед переносом уже существующего прогресса.

При `DJANGO_DEBUG=false` включаются secure cookies, перенаправление на HTTPS и базовые HSTS-заголовки; `X-Forwarded-Proto` доверяется только при работе за указанным локальным Nginx. Встроенный `runserver` предназначен для разработки.

Статическое размещение само по себе не запускает Python/Django: полноценный чат и серверная проверка версии работают после запуска этого backend на твоём сервере. Ключ не требуется помещать в браузерный JavaScript или в настройки статического сайта.
